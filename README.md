# Шаблон рабочего процесса: Godot + Claude Code

Готовый рабочий процесс для разработки игры на Godot 4 агентом Claude Code. Шаблон даёт не игру, а то, как агент работает:

- **Правила агента** — `AGENTS.md`: что читать перед работой, как спрашивать (выбор из вариантов), как экономить контекст, когда задача считается сделанной.
- **Документация с назначением у каждого файла:** `docs/HANDOFF.md` (передача дел между сессиями, ≤ 12 КБ), `TUNABLES` (рабочие значения), `KNOWN_ISSUES` (баги и техдолг), `USER_QUEUE` (что ждёт вас), `GLOSSARY`, `ARCHITECTURE`, ADR в `docs/decisions/`, `concept.md` со статусами решений «Утверждено / Рабочая основа / Рекомендация / Открыто».
- **Roadmap** — скилл `generate-roadmap`: крупная работа делится на фазы (после каждой фазы вы проверяете результат и даёте согласие) и шаги (1–3 шага на сессию агента, ~400–600 строк кода). Формат проверяет `make check`.
- **Генерация ассетов** — скилл `make-assets`: ChatGPT через Codex CLI (по подписке, без ключа API) по эталону стиля → нарезка → контрольный лист вам на одобрение → сцены объектов, листы врагов, плитка земли, куски локаций.
- **Проверки** — `make check`: gdformat, gdlint, размер HANDOFF, формат roadmap, оглавления документов, проверка ассетов, headless-тесты.
- **Инструменты Claude для Godot** — GDScript LSP (типы, переходы), MCP `godot` (агент сам запускает игру, читает интерфейс, делает скриншоты), автоформат `.gd` после правок.
- **Анализ расхода лимитов** — скилл `usage-report` по roadmap.

## Что нужно

- macOS, Linux или Windows; Godot 4.4+ (проверено на 4.7), Python 3.10+, `git`, `make`, Node.js (для MCP и Codex CLI).
- **Windows:** команды идут в Git Bash (его ставит и использует сама Claude Code). Поставить всё одной командой в PowerShell — `winget install Git.Git Python.Python.3.12 ezwinports.make OpenJS.NodeJS.LTS GodotEngine.GodotEngine`; подробности и отличия — `docs/WORKFLOW.md`, «Windows».
- Claude Code (терминал или приложение Claude, вкладка Code).
- Для генерации ассетов — подписка ChatGPT и Codex CLI (`npm i -g @openai/codex`, `codex login`).

## Как начать

### Новая игра

```bash
git clone <этот-репозиторий> my-game
```

```bash
cd my-game && rm -rf .git && git init
```

Открыть папку в Claude Code и написать:

```
Разверни рабочий процесс скиллом setup-workflow. Игра: <пара предложений об игре>.
```

### Существующий Godot-проект

Скопировать содержимое шаблона в корень проекта, не перезаписывая свои файлы (агент совместит конфликты), или просто склонировать шаблон рядом. Затем в Claude Code, открытом в папке проекта:

```
Разверни рабочий процесс из шаблона ../godot-agent-template в этот проект скиллом setup-workflow. Мой код и документы не удалять — совмести.
```

Если скилл не виден (шаблон лежит рядом и ещё не скопирован), сначала скопировать папку `.claude/skills/setup-workflow/` в проект.

Агент спросит название, суть игры, платформы, стиль графики, заполнит документы, совместит конфиги, поставит инструменты и проверит `make check`. Пару вещей сделать вам (агент подскажет команды): поставить LSP-плагин, войти в Codex, разрешить правку конфига MCP.

## Как работать дальше

- **Начало каждой сессии** агент читает `AGENTS.md` (автоматически, через `CLAUDE.md`) и `docs/HANDOFF.md`. Ничего пересказывать не нужно.
- **Крупная работа:** «Создай roadmap для <что>». Агент исследует код, пишет `docs/roadmaps/NN-*.md` и даёт промпт первой сессии. Дальше — «продолжай» в новой сессии; после каждой фазы агент спросит, переходить ли к следующей.
- **Ассеты:** «Сделай набор объектов для локации <тема>: …», «Сделай врага <кого>», «Собери локацию из готовых объектов». Ничего не попадает в игру, пока вы не одобрите контрольный лист.
- **Решения за вами** — `docs/USER_QUEUE.md`; рабочие числа, которые легко поменять, — `docs/TUNABLES.md`.
- **Расход:** «Сделай анализ расхода по родмапе NN».

## Что можно менять

Всё. Правила процесса — в `AGENTS.md` и `docs/roadmaps/README.md`; скиллы — в `.claude/skills/`. Агенту можно сказать «запомни правило …» — он внесёт его в `AGENTS.md`, и оно будет действовать во всех следующих сессиях.
