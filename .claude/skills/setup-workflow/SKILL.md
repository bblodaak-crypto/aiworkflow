# Развернуть рабочий процесс

Шаблон даёт процесс, а не игру: правила работы агента ([AGENTS.md](../../../AGENTS.md)), документы с понятным назначением, проверки и скиллы `generate-roadmap`, `make-assets`, `usage-report`. Задача — оставить процесс как есть, а содержимое (название, концепт, стиль, архитектуру) взять у пользователя или из его кода. Ничего об игре не придумывать: неизвестное — статус «Открыто» в `concept.md`.

Отвечать на языке пользователя. Документация шаблона — на русском; если пользователь выберет другой язык, переводить документы целиком, а не частями.

## 1. Где мы

Одним вызовом:

```bash
uname -s; git status --short | head; ls; grep -rl '{{' --include=*.md . | grep -v '^./.claude/skills/setup-workflow'; test -f project.godot && grep -n 'config/name\|run/main_scene\|\[autoload\]' project.godot; ls src tests addons 2>/dev/null | head -30; command -v godot codex python3 python make; echo "GODOT=$GODOT"; ls /Applications/Godot*.app 2>/dev/null
```

- **Новый проект** — в папке только файлы шаблона: всё ставится как есть.
- **Существующий проект** — файлы шаблона скопированы поверх игры (или лежат рядом в папке шаблона): совмещать по разделу 4, ничего из кода пользователя не удалять и не переписывать.

Если файлы шаблона ещё не скопированы, а пользователь дал путь к шаблону — скопировать всё, кроме `.git/` и `README.md` шаблона, не перезаписывая существующие файлы проекта: конфликты (`Makefile`, `.gitignore`, `project.godot`, `AGENTS.md`, `CLAUDE.md`, `tests/run_tests.gd`) — список, совмещение — раздел 4.

## 2. Вопросы

`AskUserQuestion`, по правилам AGENTS.md (варианты А, Б, В…, первый — рекомендуемый, с объяснением). Отдельными вызовами, не больше 4 вопросов в каждом:

1. **Об игре:** название (для `{{GAME_NAME}}`), жанр и суть в одном-двух предложениях (`{{GAME_PITCH}}`), платформы (`{{PLATFORMS}}`). Для существующего проекта — сначала предложить свою формулировку по коду и документам, пользователь правит.
2. **Стиль графики:** есть ли эталон (картинка — в `design/reference/style.png`); если нет — А. сгенерировать 2–3 пробные сцены `gen.py --scene` по описанию пользователя и выбрать (рекомендую); Б. пользователь положит картинку сам; В. пока без графики (генерация ассетов недоступна, пока нет эталона).
3. **Существующий проект:** строгая типизация — А. ошибки `untyped_declaration`, как в шаблоне (рекомендую для нового кода; старый код может перестать собираться — тогда сразу Б); Б. предупреждения; тесты — оставить свои (GUT, gdUnit4) и запускать их из `make test`, или раннер шаблона.
4. **Git:** есть ли `origin` для резервной копии (правило «push после каждого коммита»).

## 3. Заполнить шаблон

1. Заменить `{{GAME_NAME}}`, `{{GAME_PITCH}}`, `{{PLATFORMS}}`, `{{DATE}}` (сегодня, YYYY-MM-DD) во всех `.md` одним скриптом с проверкой, что после замены `grep -r '{{'` пуст (кроме этого скилла). Удалить комментарии `<!-- setup-workflow: … -->`, выполнив то, что в них сказано.
2. `concept.md`: ответы пользователя — в разделы 2–5 со статусами (сказанное пользователем — «Рабочая основа» или «Утверждено», если он так сказал; твои предложения — «Рекомендация»). Если у пользователя есть свой документ концепта — перенести его содержание в разделы с номерами, сохранив формулировки, и проставить статусы, спросив о спорных.
3. `design/ART_DIRECTION.md`: стиль словами пользователя; статус — черновик до его утверждения. `design/SPRITE_SPEC.md` — числа шаблона (4 px = 1 ед., рост героя 400 px, кадр 512) оставить, если пользователь не назвал другие; другие — поменять и в `tools/asset_rules.gd`, `tools/slice_sheet.gd`, `tools/slice_props.gd`, TUNABLES, а `make check` должен пройти.
4. `project.godot` нового проекта: `config/name`.

## 4. Существующий проект: совмещение

- **`project.godot`** — не заменять. Добавить в `[debug]` строки предупреждений шаблона (`directory_rules` для `res://.mcp` и `res://addons`, `untyped_declaration` и `unsafe_*` — по ответу из раздела 2).
- **`Makefile`** — если был свой: цели шаблона добавить, свои оставить; одноимённые — спросить. `make check` должен включать проверки шаблона и проверки пользователя.
- **`.gitignore`**, **`gdformatrc`/`gdlintrc`** — объединить. Если gdformat переформатирует весь старый код — это отдельный коммит «Format: gdformat», с согласия пользователя.
- **Тесты** — свой фреймворк пользователя оставить: `make test` вызывает его, раннер шаблона (`tests/run_tests.gd`, `test_case.gd`) и тесты инструментов (`tests/tools/`) переписать под его фреймворк или запускать отдельной целью.
- **`AGENTS.md` / `CLAUDE.md`** — если были: правила пользователя сохранить в соответствующих разделах шаблона (код, команды, особые запреты), противоречия — спросить.
- **`docs/ARCHITECTURE.md`** — «Слои и папки» и «Что существует сейчас» описать по реальному коду (Explore-агент для обзора, ключевые файлы — прочитать самому). Принципы шаблона, которым код не следует, не выдавать за действующие: убрать или записать в KNOWN_ISSUES как техдолг — по ответу пользователя. Сцены окружения шаблона (`src/scenes/locations/`, `src/scenes/common/`) — если у пользователя уже есть свои локации, спросить, нужны ли куски `LocationChunk`; не нужны — убрать их вместе с разделом «Локация» скилла `make-assets`, `tools/chunk_layout.gd`, `tools/build_chunk.gd` и их тестами.
- **Известное о коде** (баги, TODO, недоделки) — в KNOWN_ISSUES по разделам, термины игры из кода — в GLOSSARY.
- Пути шаблона (`src/scenes/locations/props`, `assets/environment`) не совпадают с проектом — поменять константы в `tools/*.gd` и пути в `make-assets`, SPRITE_SPEC, ADR-0001 одним скриптом.

## 5. Инструменты

Проверить и поставить то, что ставится без пароля; остальное — команды пользователю в отдельных блоках `bash`. На Windows (`uname -s` — `MINGW…`/`MSYS…`) — сначала WORKFLOW, «Windows»: нет `make`, Python или Godot — дать пользователю команду `winget` оттуда (PowerShell), `GODOT` — путь к `.exe`; вместо `python3` в командах — `python`.

1. `make setup` (gdtoolkit в `.venv`), `make import`, `make check`. Чинить, пока не пройдёт.
2. **LSP:** плагин ставит пользователь в Claude Code: `/plugin marketplace add minami110/claude-godot-tools`, затем `/plugin install gdscript-lsp@claude-godot-tools`; `make lsp`.
3. **MCP `godot`:** правка `~/.claude.json` — пользовательский конфиг, только с согласия: сервер `godot`, `npx -y godot-mcp-runtime`, `env`: `GODOT_PATH` (путь к Godot), `GODOT_MCP_DISABLE_ELICITATION=true` (WORKFLOW, «Инструменты Claude Code для Godot»). После правки — перезапуск приложения Claude.
4. **Codex CLI** для генерации: `npm i -g @openai/codex`, `codex login` — делает пользователь (вход в аккаунт). Затем `python3 tools/art/gen.py check`.
5. Эталон по ответу из раздела 2. Пробные сцены — `gen.py one style_a "<описание сцены игры>" --scene --out design/concepts/style-v1` — **без** эталона `gen.py` откажется: временно положить в `design/reference/style.png` любую картинку-ориентир пользователя или использовать `--provider manual`. Выбранную пользователем сцену скопировать в `design/reference/style.png`.

## 6. Завершить

1. `make toc`, `make catalog`, `make check` — проходят.
2. `docs/HANDOFF.md` — «Состояние» по факту (что за игра, что есть в коде), «Следующие шаги»: первый roadmap (предложить тему по `concept.md`), первый набор ассетов. Решения, которые пользователь отложил, — в USER_QUEUE, «Решить».
3. `git init`, если репозитория нет; коммит «Workflow: шаблон рабочего процесса» (в существующем проекте — только файлы шаблона и совмещённые конфиги, без чужих незакоммиченных правок); `git push`, если есть `origin`.
4. Коротко пользователю: что развёрнуто, что осталось сделать ему (LSP-плагин, MCP, Codex, эталон), и как начинать работу — промпт в код-блоке:

   ```
   Прочитай AGENTS.md и HANDOFF. Создай roadmap для <первая крупная работа> скиллом generate-roadmap.
   ```

Этот скилл после развёртывания не нужен: удалить папку `.claude/skills/setup-workflow/` в том же коммите, если пользователь не против.
