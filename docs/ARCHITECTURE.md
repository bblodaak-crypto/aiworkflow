## Принципы

<!-- setup-workflow: принципы шаблона; поменять, если пользователь выбрал иначе. -->

1. **Симуляция отделена от отображения.** Правила игры — чистые классы без нод. Сцены только показывают состояние и передают команды игрока. Так логику можно тестировать headless и прогонять баланс скриптом.
2. **Игра управляется данными.** Предметы, враги, уровни описываются данными (`data/*.json`), а не отдельным кодом на каждый случай.
3. **Детерминированность.** Случайность — через передаваемый генератор с сидом, а не глобальный `randf()`. Один сид и одни входные данные дают одинаковый результат.
4. **Сохранение версионируется.** У формата сохранения есть номер версии и миграции со старых версий.
5. **Минимум глобального состояния.** Autoload-ы — только для настоящих сервисов уровня приложения. Без «божественных» синглтонов и общей шины событий на всё.

## Слои и папки

```
src/
  core/      чистая логика: RefCounted/Resource, без Node, без сцен, без ввода
  systems/   связывают core с движком: тики, сохранение, загрузка данных
  scenes/    игровые сцены и их скрипты: отображение, анимация, эффекты
  ui/        экраны и виджеты интерфейса
data/        игровые данные в JSON
assets/      графика и звук, готовые к игре
tests/       headless-тесты; структура повторяет src/
tools/       скрипты разработки: проверки, нарезка и генерация ассетов
prototypes/  одноразовые эксперименты, вне правил проекта
design/      арт-направление, эталон, наборы ассетов
docs/        документация проекта
```

Папки создаются, когда в них появляется первый файл.

**Направление зависимостей:** `scenes`, `ui` → `systems` → `core`. `core` не знает о слоях выше и не обращается к `Engine`, дереву сцен, вводу и файловой системе.

Внутри сцен: вызовы идут вниз (родитель → потомок), события — вверх через сигналы. Длинные пути `get_node("../../X")` не используются.

## Что существует сейчас

### Проект и тесты

- `project.godot` — Godot 4, окно 1280 × 720, строгая типизация: `untyped_declaration` — ошибка, `unsafe_*` — предупреждения.
- Тесты — свой headless-раннер `tests/run_tests.gd` и базовый класс `TestCase` (`assert_eq`, `assert_true`, `assert_false`, `assert_almost_eq`); любая ошибка движка во время теста — провал. `make test`, фильтр — `TEST_FILTER=<подстрока пути>`.
- `make check` — gdformat, gdlint, размер HANDOFF, формат roadmap, оглавления, тесты `gen.py`, проверка ассетов, актуальность каталога ассетов, тесты.

### Сцены окружения

- `GroundShadow` (`src/scenes/common/ground_shadow.gd`) — мягкая тень под объектом или персонажем.
- `EndlessGround` (`src/scenes/locations/endless_ground.gd`) — бесконечная земля: цвет и пятна или бесшовная плитка `texture`.
- `LocationChunk` — кусок декора; `LocationView` — раскладывает куски по сетке мира вокруг видимой области (`show_area`), кусок клетки выбирается по её координатам. Корень и `Props` — y-sort.

### Инструменты

- Генерация картинок — `tools/art/gen.py` (ADR-0001). Нарезка: `tools/slice_props.gd` (листы объектов → PNG и сцены объектов), `tools/slice_sheet.gd` (листы кадров персонажей), фон снимает `tools/image_matte.gd`. Правила проверки — `tools/asset_rules.gd`, проверка папок `assets/` — `tools/check_assets.gd`.
- Куски локаций: JSON-раскладка `tools/chunks/<локация>/<кусок>.json` → сцена (`tools/chunk_layout.gd`, `tools/build_chunk.gd`).
- Каталог ассетов `docs/ASSET_CATALOG.md` — `tools/asset_catalog.gd`.
- Документация: `tools/doc_toc.py` (оглавления), `tools/roadmap_check.py` (формат roadmap), `tools/usage_report.py` (расход лимитов по roadmap).

### Чего пока нет

- Игрового кода: `src/core/`, `src/systems/`, `data/`.
