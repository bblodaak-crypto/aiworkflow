# Архитектурные решения (ADR)

Короткие записи о технических решениях, которые трудно отменить. Один файл — одно решение: `NNNN-kebab-case.md`, номера по порядку. Принятое решение не переписывается: если оно меняется, создаётся новый ADR со ссылкой «заменяет NNNN», а у старого меняется статус.

Статусы: **Предложено** (ждёт пользователя), **Принято**, **Заменено**.

## Шаблон

```markdown
# NNNN. Название

Статус: Предложено | Принято YYYY-MM-DD | Заменено NNNN
Дата: YYYY-MM-DD

## Контекст
Какую проблему решаем и какие есть ограничения.

## Решение
Что выбрали.

## Последствия
Что становится проще, что сложнее, что придётся соблюдать.

## Рассмотренные варианты
Альтернативы и почему не они.
```
