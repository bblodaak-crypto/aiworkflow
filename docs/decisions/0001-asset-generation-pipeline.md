# 0001. Генерация ассетов через ChatGPT (Codex CLI)

Дата: {{DATE}}

## Контекст

Графику делает нейросеть по одному эталону стиля `design/reference/style.png` (ART_DIRECTION). Нужен повторяемый путь «промпт → картинка → нарезка → проверка → одобрение → сцена» в одной ветке и одной сессии агента, без ручного копирования файлов.

Генератор ChatGPT доступен по подписке пользователя через Codex CLI: `codex exec` со встроенным инструментом `image_gen`, без ключа API.

## Решение

### Кто генерирует

Claude генерирует ассеты сам скиллом `make-assets`: `tools/art/gen.py` вызывает `codex exec` + `image_gen` (вызов перенесён из скилла ref2game, MIT). Платные API не используются. К каждой генерации первым прикладывается эталон `design/reference/style.png`, к вариантам утверждённого набора — его утверждённый объект как эталон формы.

### Где что лежит

| Что | Где | В git |
| --- | --- | --- |
| Источники набора: исходный лист, `PROMPTS.md` (промпты и эталоны), `README.md` (состав, одобрение) | `design/concepts/<набор>/` | да |
| Конфиги нарезки | `tools/props/<набор>.json` (окружение), `tools/sheets/<имя>.json` (листы кадров) | да |
| Нарезанные картинки | `assets/environment/`, `assets/enemies/`, `assets/ground/` | да |
| Сцены объектов и кусков локаций | `src/scenes/locations/` | да |
| Логи `codex exec`, неудачные попытки, контрольные листы до одобрения | `build/art-logs/`, `build/art/` | нет |

### Конвейер

1. Промпт по шаблону SPRITE_SPEC → `gen.py` → сырой лист в `design/concepts/<набор>/` (по 1–4 картинки за раз из-за лимита подписки).
2. Нарезка во временную папку → контрольный лист (объекты рядом с фигурой героя в масштабе игры).
3. Пользователь одобряет или даёт замечания. Сгенерированное не считается утверждённым автоматически.
4. Только после одобрения: нарезка в `assets/`, сцены, автоматическая проверка по SPRITE_SPEC (`make assets-check`), каталог (`make catalog`).

## Последствия

- Набор проходит путь от промпта до сцены за одну сессию; пользователь только одобряет контрольные листы.
- Генерация зависит от установленного и залогиненного Codex CLI и лимита подписки; расход на набор записывается в WORKFLOW.
- Уже нарезанные ассеты и сцены конвейер не перезаписывает: `slice_props.gd` не трогает существующие сцены.
- Тесты `gen.py` — без реальной генерации (подставной `codex`), чтобы `make check` не тратил лимит.

## Рассмотренные варианты

- **Платный API генерации.** Прямой вызов без Codex CLI, но нужен ключ и оплата сверх подписки.
- **Ручная генерация пользователем.** `gen.py --provider manual` оставлен как запасной путь: пишет заявку и ждёт файл.
